02FONDASI TEORI

1.1 Pengertian dan Karakteristik Data Warehouse

Dalam era transformasi digital, volume data yang dikumpulkan organisasi melonjak sangat pesat. Tantangan terbesarnya bukan kekurangan data, melainkan mengekstraksi pengetahuan dan wawasan bisnis yang bernilai dari timbunan data tersebut.

"A subject-oriented, integrated, time-variant, and nonvolatile collection of data in support of management's decision making process."

— William H. Inmon (Bapak Data Warehouse)

Empat Karakteristik Utama Data Warehouse

🎯 Berorientasi Subjek

Data disusun berdasarkan subjek bisnis utama (pelanggan, produk, penjualan, pemasok), bukan berpatokan pada proses aplikasi harian.

🔗 Terintegrasi

Data digabungkan dari berbagai sumber heterogen dengan pembersihan dan penyelarasan penamaan, kode, serta ukuran atribut.

⏱️ Bervariasi Waktu

Data disimpan dalam rentang historis panjang (5–10 tahun). Setiap struktur kunci selalu memuat elemen waktu eksplisit maupun implisit.

🔒 Non-Volatile

Data yang telah dimuat bersifat permanen dan tidak mengalami perubahan real-time; operasi utama hanyalah initial loading dan read-only access.

03KOMPARASI SISTEM

1.2 Perbedaan OLTP dan OLAP

Untuk memahami fungsi Data Warehouse, kita harus membedakan sistem On-Line Transaction Processing (OLTP) dengan On-Line Analytical Processing (OLAP).

OLTP (OPERASIONAL)

Pemrosesan Transaksi Harian

Fokus pada transaksi rutin yang cepat dan berulang.

  • Transaksi kasir, perbankan, registrasi, penggajian
  • Operasi baca/tulis rutin (read & write)
  • Menjaga konsistensi data transaksi saat ini (current)
Pengguna: Kasir, staf administrasi, DBA, praktisi IT.
OLAP (ANALITIS)

Pemrosesan Informasi & Analisis

Fokus pada analisis data historis dan penyajian multidimensi.

  • Analisis tren pasar, segmentasi, peramalan bisnis
  • Kueri kompleks dengan pembacaan scan luas (mostly read-only)
  • Mendukung pengambilan keputusan strategis manajemen
Pengguna: Manajer, eksekutif, dan analis data.

Tabel 1.1 Komparasi Antara Sistem OLTP dan OLAP

Fitur / Aspek OLTP (On-Line Transaction Processing) OLAP (On-Line Analytical Processing)
Karakteristik Pemrosesan operasional harian Pemrosesan informasi & analisis
Orientasi Sistem Transaksi (customer-oriented) Analisis pasar (market-oriented)
Pengguna Utama Kasir, staf administrasi, DBA, praktisi IT Manajer, eksekutif, dan analis data
Desain Basis Data Berorientasi aplikasi / Entity-Relationship (ER) Berorientasi subjek / Skema Bintang & Salju
Sifat Data Data saat ini (current), rinci (detailed) Data historis, teragregasi & tersimpul (summarized)
Pola Akses Data Transaksi pendek, read/write, pembaruan rutin Kueri kompleks, scan data luas, mostly read-only
Ukuran Basis Data Megabyte (MB) hingga Gigabyte (GB) Gigabyte (GB) hingga Terabyte (TB)
⚠️
Mengapa Harus Memisahkan Data Warehouse dari Basis Data Operasional?

Menjalankan kueri analisis OLAP yang kompleks langsung di atas basis data operasional (OLTP) akan menurunkan performa sistem transaksi secara drastis! Basis data operasional dioptimalkan untuk pencarian rekor individu dan transaksi cepat, sedangkan Data Warehouse dioptimalkan untuk pemrosesan agregasi dan pemindaian data berskala besar.

04STRUKTUR SISTEM

1.3 Arsitektur Tiga Tingkat (Three-Tier Architecture)

Secara umum, Data Warehouse mengadopsi arsitektur tiga tingkat untuk memisahkan lapisan penyimpanan fisik, server komputasi analitis, dan antarmuka pengguna.

TOP TIER Front-End Tools

Lapisan Antarmuka & Analisis (Front-End)

Menyediakan perkakas pelaporan (query & reporting tools), dashboard visual, alat analisis bisnis, serta perkakas Data Mining untuk pengguna akhir.

Aplikasi BI Dashboard Eksekutif Perkakas Data Mining End User
MIDDLE TIER OLAP Server

Server OLAP (Business Logic Engine)

Memetakan struktur data multidimensi ke pengguna dan memproses kueri analitis. Diimplementasikan menggunakan model ROLAP (Relational OLAP), MOLAP (Multidimensional OLAP), atau HOLAP (Hybrid OLAP).

ROLAP MOLAP HOLAP Engine Query Processing
BOTTOM TIER DW Database Server

Server Basis Data Warehouse (Fisik & Staging)

Tempat penyimpanan data fisik yang dilengkapi back-end tools dan gateway (ODBC, OLEDB, JDBC) untuk mengekstrak data dari basis data operasional dan sumber eksternal. Di lapisan ini juga terdapat staging area dan metadata repository.

Staging Area ODS Metadata Repository Gateways (JDBC/ODBC)
05AREA PERANTARA & MODEL

Operational Data Store (ODS) & Ragam Model DW

Operational Data Store (ODS) adalah area basis data logis sementara (interim area) yang digunakan sebelum data dimuat ke dalam Data Warehouse.

🧼
Pembersihan & Integrasi Data

Di dalam ODS, data dari berbagai sumber dikumpulkan, dibersihkan (scrubbed), dicek aturan bisnisnya, dan dihilangkan redundansinya.

🧠
Analogi Memori Jangka Pendek vs Panjang

ODS dianalogikan sebagai short-term memory (hanya menyimpan data operasional terkini), sedangkan Data Warehouse adalah long-term memory (menyimpan data historis permanen).

Ragam Model Data Warehouse

🏢 Enterprise Warehouse

Mengumpulkan seluruh informasi organisasi lintas fungsi dan bidang bisnis secara menyeluruh.

📦 Independent Data Mart

Data mart yang bersumber langsung dari sistem operasional tanpa melalui enterprise warehouse.

🎯 Dependent Data Mart

Data mart yang bersumber langsung dari enterprise warehouse untuk unit atau departemen spesifik.

☁️ Virtual Warehouse

Kumpulan views di atas basis data operasional tanpa membutuhkan penyimpanan fisik terpisah.

06INTEGRASI DATA

1.4 Proses Extraction, Transformation, and Loading (ETL)

ETL merupakan alur kerja krusial untuk mengambil data dari berbagai sistem sumber operasional, mengubahnya sesuai kebutuhan analisis, dan memuatnya ke dalam Data Warehouse secara berkala.

📥

1. Extraction (Ekstraksi)

Mengidentifikasi dan mengumpulkan data relevan dari berbagai basis data dan sistem aplikasi heterogen.

  • Identifikasi sumber data relevan
  • Ekstraksi dari DB relasional, teks, CSV, transaksi
  • Volume bervariasi dari MB hingga GB
  • Metode delta atau full load
⚙️

2. Transformation (Transformasi)

Mengubah format data mentah agar sesuai dengan skema dan standar Data Warehouse.

  • Pembersihan data (cleaning)
  • Standardisasi pengodean & integrasi skema
  • Penanganan missing value (nilai hilang)
  • Pembuatan surrogate key melalui proses lookup
📤

3. Loading & Refreshing

Memuat data hasil transformasi ke dalam tabel fakta dan dimensi Data Warehouse.

  • Pemuatan ke tabel fakta dan dimensi
  • Penyusunan indeks untuk optimasi kueri
  • Pembaruan agregasi data
  • Penjadwalan refresh data secara berkala
07DIREKTORI DATA

1.5 Metadata Repository dan Pengelolaannya

Metadata secara sederhana didefinisikan sebagai "data mengenai data" (data about data). Dalam Data Warehouse, metadata berfungsi sebagai direktori dan road map yang memandu pengguna serta sistem untuk menemukan, memetakan, dan mengelola isi gudang data.

Tiga Kategori Utama Metadata

Business Metadata

Metadata Bisnis

Berisi definisi istilah bisnis, informasi kepemilikan data (data ownership), serta kebijakan perubahan aturan bisnis yang berlaku di organisasi.

Technical Metadata

Metadata Teknis

Berisi nama sistem basis data, nama tabel dan kolom, tipe data, batasan nilai (constraints), struktur kunci utama/asing (primary/foreign keys), serta informasi skema data.

Operational Metadata

Metadata Operasional

Berisi status aktualitas data (currency of data)—apakah data aktif, diarsipkan, atau dihapus—serta riwayat silsilah data (data lineage) proses migrasi dan transformasi.

📚
Peran Metadata Repository

Metadata Repository menyimpan deskripsi skema Data Warehouse, aturan pemetaan (mapping rules) dari lingkungan operasional ke DW, algoritma agregasi, profil performa sistem, serta riwayat penjadwalan refresh data.

08KESIMPULAN & DISKUSI

Rangkuman Bab 1 & Latihan Soal Diskusi

Berikut adalah ringkasan pokok materi beserta pertanyaan diskusi dari Lecturer Note Week 1 untuk menguji pemahaman konsepmu.

Poin Kunci Rangkuman

  • Data Warehouse adalah repositori data terpusat yang bersifat subject-oriented, integrated, time-variant, dan nonvolatile untuk mendukung pengambilan keputusan.
  • Sistem OLTP melayani transaksi operasional harian (read/write), sedangkan sistem OLAP melayani kueri analisis multidimensi historis (mostly read-only).
  • Arsitektur Data Warehouse terdiri dari tiga tingkat: Bottom Tier (server database & ODS), Middle Tier (server OLAP), dan Top Tier (front-end tools & Data Mining).
  • Proses ETL (Extraction, Transformation, Loading) adalah tahapan utama dalam mengintegrasikan data heterogen ke dalam Data Warehouse.
  • Metadata bertindak sebagai direktori yang mencatat informasi bisnis, teknis, dan operasional seluruh objek dalam Data Warehouse.
